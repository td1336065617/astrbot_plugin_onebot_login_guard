# OneBot 登录守护（astrbot_plugin_onebot_login_guard）设计文档

> 版本：v1.0（草稿）　|　配套：`docs/需求分析.md`
> 目标环境：AstrBot >= 4.13（实测 4.27.3 / 4.28.0）、OneBot v11（NapCat / Lagrange / go-cqhttp）
> 状态：待评审

---

## 1. 总体架构

```
                 ┌──────────────── main.py (Star) ────────────────┐
                 │  initialize(): 启动守护循环 + 注册 Web API      │
                 │  hooks: on_astrbot_loaded / on_platform_loaded  │
                 │  commands: 登录守护状态 / 二维码 / 测试         │
                 └───────────────┬────────────────────────────────┘
                                 │
                 ┌───────────────▼────────────────┐
                 │      Guard（状态机 + 调度）      │
                 │  轮询 → 探测 → 状态转移 → 去重   │
                 └───┬───────────────┬────────────┘
                     │               │
        ┌────────────▼──────┐   ┌────▼─────────────────────┐
        │  Probes（探测层）  │   │  Notifiers（通知层）      │
        │  · AstrBotProbe   │   │  · AstrBotSessionNotifier │
        │  · LogFileProbe   │   │  · WebhookNotifier        │
        │  · QrFileProbe    │   │    (wecom/dingtalk/feishu │
        │  · HttpProbe(可选) │   │     /telegram/generic)    │
        └───────────────────┘   └──────────────────────────┘
                     │               │
                 ┌───▼───────────────▼───┐
                 │  Store（事件/状态落盘） │
                 └───────────────────────┘
```

设计原则：

1. **探测与通知解耦**：探测源、通知渠道都可插拔，新增协议端/渠道不改核心。
2. **宁可不报，不可误报**：探测不确定时判 UNKNOWN，不触发通知。
3. **通知要快、要稳、要能跨 AstrBot**：优先 AstrBot 会话，同时支持外部 Webhook。
4. **零侵入**：只读协议端日志/二维码文件，不修改协议端。

## 3. 数据模型（core/models.py）

```python
class LoginState(str, Enum):
    ONLINE = "online"          # 已登录、连接正常
    OFFLINE = "offline"        # 进程不在 / 反向 WS 断开（无二维码）
    NEED_LOGIN = "need_login"  # 需要人工扫码
    UNKNOWN = "unknown"        # 探测不可用 / 不确定

@dataclass
class ProbeResult:
    instance_id: str           # 被守护实例 ID
    state: LoginState
    source: str                # astrbot / logfile / qrfile / http
    detail: str = ""           # 人读说明
    qr_path: str = ""          # 二维码图片绝对路径
    qr_url: str = ""           # 二维码解码 URL
    qr_hash: str = ""          # 二维码指纹（文件 md5 或 URL 摘要）
    ts: int = 0

@dataclass
class GuardEvent:
    kind: str                  # need_login / offline / recovered / qr_refreshed
    instance_id: str
    state: LoginState
    qr_path: str = ""
    qr_url: str = ""
    qr_hash: str = ""
    ts: int = 0

@dataclass
class NotificationRecord:
    event_kind: str
    instance_id: str
    channel: str               # astrbot:<umo> / webhook:<type>
    ok: bool
    error: str = ""
    ts: int = 0
```

## 4. 探测层设计（core/probes.py）

统一协议：

```python
class BaseProbe(Protocol):
    name: str
    async def probe(self, instance: InstanceConfig) -> ProbeResult: ...
```

### 4.1 AstrBotProbe（始终可用）
- 通过 `context.get_platform_inst(platform_id)` 拿到 aiocqhttp 平台实例；
- 判定：
  - 平台状态为 `PlatformStatus.ERROR` → OFFLINE；
  - `bot._wsr_api_clients` / `bot._wsr_event_clients` 均为空 → OFFLINE；
  - 否则 ONLINE。
- 拿不到实例 → UNKNOWN。
- 优点：零配置、跨主机也能用；缺点：区分不出「进程挂了」和「要扫码」，也拿不到二维码。

### 4.2 LogFileProbe（推荐，能拿到二维码）
- 记录 `offset`，增量读取协议端日志（默认只读尾部 N KB）；
- 内置正则模板 + 可覆盖：

| 语义 | NapCat 样例 |
| --- | --- |
| need_login | `Login Error,ErrType:` / `请扫描下面的二维码` / `二维码已保存到` |
| qr_url | `二维码解码URL:\s*(\S+)` |
| online | `登录成功` / `[Login] Success` |

- 文件不存在 / 不可读 → 返回 UNKNOWN（不误报），并在状态页提示「路径配置有误」。

### 4.3 QrFileProbe（二维码刷新检测）
- 读取 `qr_path`（默认 NapCat 的 `.../napcat/cache/qrcode.png`）；
- 计算 md5 作为 `qr_hash`；mtime / md5 变化 → 视为「二维码已刷新」。

### 4.4 HttpProbe（可选，跨主机场景）
- 调用 NapCat WebUI API（`http://127.0.0.1:6099` + token）获取登录状态 / 二维码；
- 作为跨主机时的二维码来源。

### 4.5 探测组合
一个实例可配置多个探测源，按优先级合并：
`HttpProbe → LogFileProbe(+QrFileProbe) → AstrBotProbe`
高优先级源能给出明确结论时采用；否则逐级降级。

## 5. 状态机与调度（core/guard.py）

### 5.1 调度
- `initialize()` 里 `asyncio.create_task(guard.run())`，`terminate()` 取消；
- 循环间隔 `poll_interval`（默认 30s，可配 10~600）；
- 每次循环对所有被守护实例并发探测。

### 5.2 状态转移与通知

| 上一状态 | 新状态 | 动作 |
| --- | --- | --- |
| ONLINE / UNKNOWN | NEED_LOGIN | 发 `need_login`（带二维码） |
| NEED_LOGIN | NEED_LOGIN（qr_hash 变化） | 发 `qr_refreshed`（可开关） |
| NEED_LOGIN | NEED_LOGIN（hash 不变） | 静默 |
| ONLINE / UNKNOWN | OFFLINE | 发 `offline`（连续 N 次确认后，无二维码） |
| NEED_LOGIN / OFFLINE | ONLINE | 发 `recovered` |
| 任意 | UNKNOWN | 静默（只在状态页展示） |

### 5.3 去重与冷却
- 幂等键：`instance_id:kind:qr_hash`；
- `notify_cooldown`（默认 600s）：同 key 在窗口内不重复发；
- `offline_confirm_rounds`（默认 2）：连续 N 次判 OFFLINE 才发，避免抖动误报。

### 5.4 抖动防护
- 进程重启期间会短暂 OFFLINE → 由 `offline_confirm_rounds` 吸收；
- 二维码刷新很频繁时 → 由 `qr_refresh_notify` 开关 + 冷却控制。

## 6. 通知层设计（core/notifiers.py）

```python
class BaseNotifier(Protocol):
    channel_id: str
    async def send(self, event: GuardEvent, qr_path: str, qr_url: str) -> bool: ...
```

### 6.1 AstrBotSessionNotifier
- 配置 `notify_sessions: ["<umo>", ...]`；
- 发送：`context.send_message(umo, MessageChain([Plain(text), Image.fromFileSystem(qr_path)]))`；
- 渠道不支持图片时（异常）降级为纯文本 + URL；
- **关键价值**：可把二维码发到「另一个还活着的平台」（QQ 官方号 / Telegram / 企微），实现跨通道自救。

### 6.2 WebhookNotifier
支持类型：`wecom`（企业微信）、`dingtalk`（钉钉）、`feishu`（飞书）、`telegram`、`generic`、`email`（SMTP 邮件）。

| 类型 | 载荷要点 |
| --- | --- |
| wecom | `{"msgtype":"image","image":{"base64":...,"md5":...}}`，或 text 带 URL |
| dingtalk | markdown + `@手机号`（可选） |
| feishu | `{"msg_type":"text","content":{"text":...}}` |
| telegram | `sendPhoto`（multipart）或 `sendMessage` |
| generic | `POST {event, instance_id, state, qr_url, text}` |
| email | SMTP 发送（SSL / STARTTLS），二维码作为附件 |

- 统一用 `aiohttp.ClientSession`，超时 / 重试（指数退避，最多 3 次）；
- 失败只记 `NotificationRecord(ok=False)`，不影响其它渠道。

### 6.3 消息模板

```
🔐 OneBot 登录守护
实例：<instance_id>
状态：需要重新登录
时间：<ts>
请在 2 分钟内用手机 QQ 扫描下方二维码。
二维码解码链接：<qr_url>
```

| 方法 | 路由 | 说明 |
| --- | --- | --- |
| GET | `/onebot_login_guard/status` | 各实例当前状态 + 最近探测详情 |

| POST | `/onebot_login_guard/resend_qr` | 重发二维码（忽略冷却） |
| POST | `/onebot_login_guard/test_notify` | 发一条测试通知 |
| GET | `/onebot_login_guard/events` | 最近事件列表 |
| GET | `/onebot_login_guard/qr` | 返回二维码图片（file_response） |
| GET | `/onebot_login_guard/events/stream` | SSE 实时事件 |

响应统一用 `json_response / error_response / file_response / stream_response`。

## 11. 关键流程（掉登录 → 恢复）

```
Guard.run()  每 30s
   │
   ├─ LogFileProbe 读到 "Login Error" / "请扫描"  → NEED_LOGIN
   ├─ QrFileProbe 读到 qrcode.png（md5=H1）
   │
   ├─ 状态转移 ONLINE → NEED_LOGIN
   │     ├─ 幂等键 inst:need_login:H1 未在冷却内
   │     ├─ AstrBotSessionNotifier 发送（文本 + 二维码图片）
   │     ├─ WebhookNotifier 并发发送（企微 / Telegram …）
   │     └─ Store 记录 GuardEvent + NotificationRecord
   │
   ├─ 下一轮：二维码刷新（md5=H2）→ 发 qr_refreshed（若开启）
   │
   └─ LogFileProbe 读到 "登录成功" → ONLINE → 发 recovered
```

## 12. 兼容、降级与边界

| 情况 | 行为 |
| --- | --- |
| 日志路径未配置 / 不存在 | 跳过 LogFileProbe，状态页提示；不误报 |
| 协议端与 AstrBot 不同主机 | 仅 AstrBotProbe；能报「掉线」，拿不到二维码（文档说明） |
| 平台实例 ID 变更 | 按 `platform_id` 匹配；找不到 → UNKNOWN |
| 多个 OneBot 实例 | 每个实例独立状态机与冷却 |
| 二维码文件被清理 | 保留最近一次成功读取的副本到 `data/`，避免「拿到了但发不出去」 |
| 通知渠道全部失败 | 记录失败并降级为写日志（保证可追溯） |

## 13. 测试计划

**单测（pytest）**
- 正则解析：内置 NapCat / Lagrange / go-cqhttp 日志样本 → 状态与 qr_url 提取。
- 状态机：ONLINE→NEED_LOGIN→qr 刷新→ONLINE 的转移与通知次数。
- 冷却 / 幂等：同 key 不重复；qr_hash 变化会重发。
- 抖动：连续 1 次 OFFLINE 不发、2 次才发。
- Notifier 载荷：wecom / dingtalk / feishu / telegram / generic 的 body 断言（mock aiohttp）。
- 配置解析与脱敏。

**集成**
- FakeProbe + FakeNotifier 驱动完整流程。
- Web API 契约测试（status / probe / resend_qr / test_notify）。

**真机演练**
- 在 NapCat 上执行登出（或停进程）→ 验证 ≤ 2 个周期内收到二维码 → 扫码 → 收到恢复通知。
